LangGraph, from first principles

Not just "here's what this one agent does" — the vocabulary, the motivation, and the mechanics, built up from the same small example (Module 1's calculator agent) so the ideas generalize past it.

1. Why a graph at all

A single prompt can't loop. An agent needs to.

A plain LLM call is a one-shot: text in, text out, done. The moment you need the model to check something, act, look at the result, and decide again — you need a loop with a decision in it. That's all a LangGraph graph is: nodes you write, connected by edges that say "go here next," with one edge allowed to ask "which next?" based on what just happened.

Single LLM call

Prompt in → text out. If the model needs to do arithmetic, it has to "mentally" guess — there's no way for it to pause, compute something exactly, and resume with the real number.

prompt→LLM→text
vs.

LangGraph agent

The model can request a real tool call, get the exact result back, and decide again — as many times as it needs — before answering. The loop is the point.

2. The same skeleton, every time

From one node to a loop

Module 0's hello-world graph and Module 1's calculator agent are built from the exact same parts — StateGraph, nodes, edges. Module 1 just adds one branch and one loop-back edge. Every bigger agent you'll meet later (multi-tool, multi-agent, human-in-the-loop) is this same skeleton with more nodes and edges added on top — nothing about the primitives changes.

Module 0 — one node, no choices

START always goes to the one node, which always goes to END. No branching, no memory of tool use, because there's no tool.

Module 1 — a decision and a loop

Same START/END ends. One extra node (tools), one conditional edge (a decision), one edge back (the loop). That's the entire delta.

4. This specific agent

Before the trace — the four questions any agent explainer should answer

Reasoning

Happens entirely inside the Groq-hosted LLM at llm_with_tools.invoke(). LangGraph does no reasoning itself — it only routes based on whether the LLM's response contains tool_calls.

Memory

None persisted. state["messages"] is working memory for one invoke() call only — no checkpointer is attached at .compile(). Streamlit fakes cross-turn history by resending the full list each time; refresh the page and it's gone.

Tools

One: calculator, a numexpr-based arithmetic evaluator bound via bind_tools. No search, no retrieval.

Goal & end criteria

Answer the question, routing arithmetic through the real tool. Halts when agent_node returns an AIMessage with an empty tool_calls list — no max-loop cap exists yet.
